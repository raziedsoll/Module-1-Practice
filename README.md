# Первый запуск

1. Запуск Kafka и UI:

```bash
docker compose --profile kafka up -d --wait
```

2. Создание топика, если его ещё нет:

```bash
docker compose exec kafka-1 kafka-topics \
--bootstrap-server kafka-1:29092 \
--create --topic Message \
--partitions 3 --replication-factor 2
```

3. Запуск двух экземпляров приложения:

```bash
docker compose --profile app up -d --build
```

Профиль app запускать после готовности Kafka.

4. Посмотреть логи обеих реплик приложения

```bash
docker compose logs -f app
```

5. Повторный запуск

```bash
docker compose --profile kafka up -d --wait &&
docker compose --profile app up -d
```
Если при повторном запуске упала ошибка, а конкретно если несколько брокеров не запустилось, надо повторить запуск компоуза командой выше.

# Описание классов

- `Module1PracticeApplication` — точка входа: запускает Spring Boot и работу с Kafka.
- `KafkaIntegration` — запускает продюсер и двух консьюмеров в отдельных виртуальных потоках и останавливает их при завершении приложения.
- `MessageProducer` — каждые две секунды создаёт тестовое сообщение и отправляет его в Kafka в формате JSON.
- `SingleMessageConsumer` — читает сообщения по одному и выводит их в лог. Offset коммитится автоматически.
- `BatchMessageConsumer` — получает сообщения батчами, выводит их в лог и затем вручную коммитит offset.
- `Message` — само сообщение: отправитель, получатель и текст.
- `KafkaConfigurationProperties` — хранит настройки Kafka из конфигурации приложения: адрес брокера, топик и параметры продюсера и консьюмеров. Вложенные записи `MessageProducerConfig`, `SingleMessageConsumerConfig` и `BatchMessageConsumerConfig` объединяют настройки каждого из них.

# Шаги для проверки

- Запускаем кластер, создаем топик, запускаем два экземпляра приложения.
- Смотрим логи приложения. Там увидим работу продюсера и консьюмеров.
- Можно так же перейти в Kafka UI по адресу http://localhost:8080 и посмотреть генерацию сообщений в лайф режиме. Там же можно увидеть две консьюмер группы, количество брокеров.
- В Kafka UI можно отправить сообщение с содержимым, отличным от содержимого класса Message. В таком случае в логах можно отследить ошибки десериализации.
